# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated: chosen per project by the agent, with the choice and reason recorded in that project's own brief or README. Default lean: plain static HTML/CSS/JS with no build step, unless a project's needs justify a framework.

## Users

The repository owner, working alone. Projects are personal R&D: learning, testing ideas, and building small tools for their own use. No public or external audience is confirmed.

## Product Purpose

Mini-Projects is a collection of small, unrelated experiments, prototypes and demos. Each project stands alone. Success means a project answers the question it was started for, or does its job for its one user, quickly and without ceremony.

## Operating Context

Each experiment lives in its own folder in this repository. Work happens largely with AI coding agents, including cloud sessions. Projects may be abandoned, revisited or remixed, so each one should be understandable on its own.

## Capabilities and Constraints

- This file holds shared context only. Each project's specifics (purpose, users, mode) belong in that project's own brief, not here.
- No shared design system or visual world exists. One is not assumed; each experiment may choose its own unless a shared one is later decided.
- Undecided: folder layout conventions, hosting and deploy target.

## Evidence on Hand

None yet. The repository contains only `README.md`. No content, data, users, testimonials or assets exist, and future work must not invent any.

## Product Principles

1. Each experiment stands alone: no hidden coupling between projects.
2. Prefer the lightest thing that answers the question.
3. Built for one real user, so optimize for usefulness to the owner, not for marketing.
4. Leave enough of a note in each project to pick it back up later.
